## Objective

Expose a bounded, read-only observation of the active v4 browser state without exporting form values or internal checkpoint traversal. Bind each model-visible element ID to a uniquely verified target.

## Behavior and flow

1. Add `VisualWorkerObserveDom` and response models using existing v4 identity/fencing plus expected state fingerprint, snapshot ID, element/byte caps. Expose private POST `/visual-explorations/{session_id}/observations/dom` with the existing worker secret and scope validation.
2. Advertise a named `dom-observation-v1` capability in open/readiness response. A Codex session encountering an old worker fails clearly before sending any observation to Codex. Do not reinterpret absence as empty DOM.
3. Take observations while no physical operation is pending. Reuse `inspectState` for before/after equality without serializing `privateForms`. Reject a page that changes during collection; no stale fallback.
4. Enumerate visible interactive elements with deterministic ordering and bounded traversal. Include semantic buttons, links, inputs, textarea/select and role-based controls. Extract role/name safely; never serialize current input values, contenteditable contents, hidden nodes, scripts, passwords, cookies or raw HTML.
5. Sanitize accessible labels/attributes using shared redaction rules; strip/redact credential-like and personal-data patterns, cap label length, and expose only safe control metadata. Pixel redaction is not promised. Tests include secrets in aria-label, title, text and test-id.
6. Use existing unique/actionable locator validation and normalized bounds for trusted bindings. IDs are observation-scoped opaque references. Skip controls without a safely resolvable identity; report counts/reasons rather than invent selectors.
7. Bound open-shadow/iframe traversal. Reuse existing scope validation for supported frames; identify unsupported frames/closed shadow/canvas without leaking contents or relaxing scope checks. Indicate truncation, missing coverage and scrollability so a planner can scroll or request an image.
8. Cache the bounded snapshot binding in the worker session with its identity/fingerprint; clear on close/expiry. For every DOM proposal, resolve the saved descriptor afresh after restoration and verify state, uniqueness, visibility, actionability and target hit-test. A changed element or stale snapshot is rejected.
9. Extend the existing prepare request with optional DOM snapshot/element reference fields (required together for this mode). Obtain current coordinates from the verified live binding at prepare rather than trusting stale model coordinates. Preserve recorded before/after evidence and confirmed click contract; coordinate/image proposals continue through existing grounding.
10. The Python transport validates response scope, version/capability, fingerprint, element count, bytes and IDs. It returns typed observation data through the port, without logging DOM bodies.

## API/schema impact

The private observation endpoint is additive. Prepare's optional DOM reference is a declared capability extension; old producers remain valid. Codex requires the capability. Public execution v1 is unchanged. Generate TypeScript schema from Python; no handwritten parallel contract. Do not persist raw observations in activity JSON.

## Acceptance, risks and non-goals

DOM response is bounded, sanitized and corresponds to one stable browser state. A DOM reference cannot select a different element after reorder, navigation or restoration. Existing image proposals pass regressions. This is not a full DOM dump, universal accessibility crawler, OCR engine or new runner. Unsupported targets remain explicit limitations.
