## Cause

playwright-worker log, `POST /visual-explorations`, stage `session_open`:
`code=invalid_deadline`, HTTP 422 (`reports/phase-06/live-session-failure-evidence.log`). The worker accepts an open only when
`deadline <= now + max_session_seconds` (`workers/playwright/src/vision-operations.ts:140`). The agent loop sets
`deadline = started + min(3600, step_timeout x max_calls)` = 2400 s (`application/vision_agent_loop.py:296-301`) but sends
`max_session_seconds = step_timeout_seconds` = 120 (`:351-353`). v4 opens with `now + step_timeout` and renews the worker
deadline per step (`step_deadline`). Subsequent worker calls (`/origins`, `DELETE`) returned `session_unavailable`.
Unit tests did not catch it because the fake worker does not enforce that rule.

This is a control-plane defect in the phase 4 code, outside the files phase 6 may change; it is **not** a bridge, token or
stack problem (control-plane healthy, claude-bridge idle with no job submitted). The probable fix is to open the worker
session with a deadline of `now + step_timeout` (as v4) while keeping the session-level deadline for the loop, plus a test that
applies the worker's rule. The user decides whether to open a small phase and a second live round.
